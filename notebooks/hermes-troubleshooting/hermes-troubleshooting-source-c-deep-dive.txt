Hermes Agent Production Debugging Deep-Dive
============================================

1. GATEWAY 故障根因分析

Gateway 是 Hermes Agent 与消息平台之间的桥梁。大部分"命令执行失败"的
根因在 Gateway 层。

1.1 日志分析三看：
   第一看: hermes gateway status → 确认各平台连接状态
   第二看: grep -i "error\|fail\|exception\|traceback" ~/.hermes/logs/gateway.log | tail 50
   第三看: journalctl -u hermes-gateway --no-pager -n 50（如果是 systemd 服务）

1.2 平台特有故障：

   飞书 (Feishu/Lark):
   - 应用过期: 飞书应用 token 有效期仅 2 小时，需 app_id + app_secret 自动刷新
   - 权限不足: 需要 im:message 权限和 im:resource（图片上传）
   - Markdown 限制: 飞书不渲染表格、列表首行不能用特定标记
   - 排查: 检查 ~/.hermes/logs/gateway.log 中是否含 "feishu" 和 "access_token expired"
   - 修复: hermes gateway restart（重新初始化所有平台连接）

   Telegram:
   - Bot Token 被撤回: 父机器人终止或被他人占用
   - 群组权限: bot 需要被添加为群管理员才能读取消息
   - 消息长度限制: Telegram 单个消息 4096 字符上限
   - 修复: /start 重新激活或 botfather 重新生成 token

   Discord:
   - Intent 未启用: bot 需要 Message Content Intent
   - 分片初始化失败: 大型服务器需要调整 shard 数量
   - 修复: 检查 Developer Portal 中 Privileged Gateway Intents

1.3 Gateway 连接调试序列：
   Step 1: hermes gateway status         # 快速状态检查
   Step 2: hermes gateway run            # 前台启动，看实时日志
   Step 3: 在另一个终端发送测试消息      # 观察日志输出
   Step 4: grep "connected\|disconnected\|auth" ~/.hermes/logs/gateway.log

2. PROVIDER 故障深层排查

2.1 多 Provider 负载均衡问题：
   - Hermes 支持 credential pools（多个 API Key 轮换）
   - 当一个 Key 触发 rate limit，会自动切换到池中下一个
   - 症状: 间歇性"Provider returned error"后自动恢复
   - 排查: hermes auth list [provider] → 查看池中 Key 状态
   - 修复: hermes auth reset <provider> → 重置 exhaustion 状态

2.2 智能路由 (Smart Model Routing)：
   - 配置: config.yaml 中 smart_model_routing.enabled: true
   - 机制: 简单任务走 cheap_model，复杂任务走主模型
   - 症状: 逻辑推理任务（如代码生成）突然换成小模型，质量下降
   - 排查: 查看回复中是否出现 "reasoning" 或 provider 信息不一致
   - 修复: 设置 smart_model_routing.enabled: false 或调整阈值

2.3 自定义 Provider (custom_providers)：
   - 症状: 配置了自定义 endpoint 但一直超时
   - 常见原因: base_url 缺少 /v1/chat/completions 路径
   - 正确格式: base_url: "https://your-api.com/v1" （框架自动补全路径）
   - 测试: curl -X POST "https://your-api.com/v1/chat/completions" -H "..." -d "..."

3. MEMORY 系统故障详解

3.1 内存写入失败（最常见原因）：
   - MEMORY.md 硬限制: 2,200 字符
   - USER.md 硬限制: 1,375 字符
   - 检测: wc -m ~/.hermes/memories/MEMORY.md
   - 注意: 这是硬限制，不是软限制。超过 95% 时 memory tool 即拒绝写入
   - 修复不是"改大限制"而是"清理内容"

3.2 内存文件损坏：
   - 症状: memory() 返回成功但后续读取失败
   - 修复: 手动编辑 ~/.hermes/memories/MEMORY.md 检查 YAML frontmatter
   - 预防: 禁止写入二进制/不可序列化内容

3.3 会话存储 (SQLite) 问题：
   - 位置: ~/.hermes/sessions/hermes.db
   - 症状: hermes sessions list 变慢或卡住
   - 原因: 会话过多（默认 30 天），或数据库损坏
   - 修复: hermes sessions prune --older-than 30

4. CRON 任务故障排查

4.1 任务未执行：
   - 检查 scheduler 是否运行: ps aux | grep hermes | grep scheduler
   - 默认 scheduler 是 gateway 的一部分，需确保 gateway 在运行
   - 检查 cron 日志: cat ~/.hermes/logs/cron.log

4.2 任务执行了但没收到结果：
   - 交付目标问题: cron 在无会话上下文中执行，需要明确 deliver 目标
   - 检查 config.yaml 中 cron 的 delivery 配置
   - 手动触发调试: hermes cron run <id>

4.3 脚本模式 (no_agent=True) 报错：
   - 脚本 exit code 非 0 时 cron 记录 error 但不自动重试
   - 脚本 stdout 空 = 静默不发送（不是失败）
   - 调试: 直接运行脚本看输出

5. TOOL 调用调试技术

5.1 使用 verbose 模式查看完整调用链：
   - CLI: hermes chat -v 或 /verbose 在会话中
   - 会显示每个 tool 调用的输入参数和返回结果

5.2 工具返回值验证：
   - 某些工具（如 delegate_task）的实现是"自报告"的
   - 子代理声称"上传成功"可能实际失败
   - 验证原则: 对于有外部副作用的操作，要求子代理返回可验证的句柄
     （URL、文件路径、HTTP 状态码），主代理验证后再告诉用户

5.3 batch 工具调用限制：
   - delegate_task 的 max_concurrent_children=3 是硬限制
   - 超过 3 个批量任务必须分批调用
   - 原因: 避免系统资源耗尽

6. 配置文件注入 (高级)

   当 CLI 工具不可用（headless 环境、非交互 shell）:
   可以直接用 Python 修改 config.yaml:

   python3 -c "
   import yaml
   with open('/root/.hermes/config.yaml') as f:
       cfg = yaml.safe_load(f)
   # 修改配置
   cfg['model']['provider'] = 'deepseek'
   cfg['agent']['max_turns'] = 120
   with open('/root/.hermes/config.yaml', 'w') as f:
       yaml.dump(cfg, f)
   "

   注意: 修改后 gateway 需要重启才能生效
         会话内配置需要 /reset 才能生效

7. 诊断清单速查

   当用户说"命令执行失败"时，按优先级排查:

   [P0] hermes doctor --fix               → 基础依赖和环境
   [P0] hermes config check               → 配置有效性
   [P1] hermes tools list                 → 工具集状态
   [P1] grep -i error ~/.hermes/logs/*.log | tail 30  → 日志
   [P2] hermes gateway status             → 平台连接
   [P2] cat ~/.hermes/.env               → API Key 状态
   [P3] hermes model                      → 模型/Provider
   [P3] hermes cron list                  → 定时任务
   [P4] hermes sessions list              → 会话状态
   [P4] wc -m ~/.hermes/memories/*.md     → 内存饱和度
